# SAEF Step 396: HTML SDK Map And Statistics Design

**Case study:** Navimow native IP-Symcon module

**Status:** Additive HTML SDK design accepted for offline implementation

**Date:** 2026-09-12

## 1. Purpose

The existing HTMLBox map is a useful fallback but cannot provide ergonomic
browser and app zoom. This step defines an additive IP-Symcon HTML SDK surface
for the local Navimow map and mowing statistics.

## 2. Presentation Contract

The Device instance becomes an HTML fullscreen visualization when the current
Symcon runtime supports that type. The existing `LocalMap` HTMLBox variable is
retained unchanged as a compatibility and rollback surface.

The HTML SDK tile provides:

- an edge-to-edge map surface;
- wheel and button zoom;
- pointer drag pan;
- two-pointer pinch zoom without rotation;
- `Fit`;
- follow-current-mower mode;
- one focus target per configured map zone; and
- a compact horizontally scrollable zone-statistics strip.

No browser-side request, tile provider, external font or network dependency is
permitted.

## 3. Renderer Reuse

The existing server-side SVG remains the single source of map semantics:

- zone, obstacle and track layers;
- task-attribution diagnostics;
- REST-authoritative station and mower state colors;
- directional mower glyph;
- dock occupancy glyph;
- position-freshness halo; and
- symbol legend.

The HTML SDK client only changes the SVG `viewBox` and renders bounded textual
statistics. It does not reinterpret coordinates or state.

## 4. Visual Corrections

The accepted visual changes are:

- rotate only the rendered station glyph 8 degrees counterclockwise;
- reduce the general scene margin to 1 percent with a 0.25-unit minimum;
- preserve explicit station and mower safety extents to prevent clipping;
- keep the Dark Skin surface edge-to-edge;
- retain strong magenta unknown and red attention colors;
- retain the directional mower shape instead of a circle;
- distinguish an empty station from a station containing the mower; and
- show 7/14-day recency as yellow/red outlines without replacing the base zone
  color.

## 5. Client State

The client preserves pan and zoom when a new message has the same geometry
revision. A changed geometry resets to Fit and rebuilds the zone selector.
Manual pan, zoom or zone focus turns follow mode off. Follow mode recenters on
each fresh render.

All labels are assigned through `textContent`. The SVG is generated by the
trusted bounded server renderer. The complete visualization message is capped
before it reaches the browser.

## 6. HTML SDK Choice

Navimow uses a local Cartesian garden map with no basemap or tile service.
Native SVG viewBox navigation is therefore smaller and preserves the already
qualified renderer exactly. OwnTracks still benefits from OpenLayers for
geographic coordinates and provider-neutral basemaps. Both integrations share
the HTML SDK lifecycle pattern without forcing the same map engine.

## 7. Accessibility And Responsive Layout

- Controls use native buttons and a select element with labels and titles.
- Pointer gestures are confined to the map surface.
- Coarse-pointer controls receive larger hit targets.
- Below 680 pixels, the zone selector receives its own row.
- The statistics strip scrolls horizontally and never resizes the map.
- Status feedback is an ARIA live region.

## 8. Architecture Decisions

### AD-NAV-396-01: Add HTML SDK without deleting HTMLBox

An additive transition preserves the installed variable identity and gives a
configuration-first rollback if a client cannot render the fullscreen tile.

### AD-NAV-396-02: Keep navigation client-local

Pan, zoom and focus do not require a Symcon action or configuration mutation.

### AD-NAV-396-03: Keep map engines provider-specific

The shared architectural boundary is the HTML SDK message lifecycle. A local
SVG map and a geographic OpenLayers map need not share rendering internals.
