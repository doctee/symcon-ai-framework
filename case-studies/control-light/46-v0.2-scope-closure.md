# ControlLight v0.2 Scope Closure

**Gate:** Rollout scope and legacy disposition
**Result:** PASS - SEVEN V2 SELECTED, 22 LEGACY RETAINED
**Date:** 2026-07-21
**Live impact:** None

## Decision

The ControlLight scope for the SAEF v0.2 rollout is closed with seven active
v2 wrappers and 22 intentionally retained legacy wrappers.

All seven selected wrappers:

- use the current hash-addressed ControlLight fileset;
- passed two-run idempotent configuration;
- preserve owned object, presentation, archive and event contracts;
- use explicit `reported` brightness semantics;
- completed bounded real-device testing for every enabled capability; and
- remain part of the complete 29-wrapper source regression.

The remaining 22 wrappers are classified **RETAIN** for this rollout. Retain is
an explicit compatibility decision, not missing inventory or failed v2 code.

## Why Bulk Migration Is Rejected

The remaining inventory contains materially different contracts:

- link-dependent state, brightness, temperature and full-color consumers;
- external-trigger behavior;
- off-state presentation differences under `reported` semantics;
- unresolved or intentionally inert target-action contracts;
- a hard-powered-off target without current feedback evidence; and
- a non-operational template with no enabled capability.

A repository release does not authorize changing those private consumers. A
single bulk migration would combine unrelated semantics, weaken rollback and
turn valid installation-specific exceptions into accidental framework rules.

## Future Migration Boundary

A retained wrapper may move to v2 only through a later, separately approved
cohort that provides:

1. explicit brightness semantics and downstream-consumer review;
2. fresh target action and authoritative-feedback evidence;
3. exact source, topology, presentation and archive baselines;
4. a hash-locked candidate and recoverable rollback image;
5. two-run non-commanding configuration and full-wrapper regression; and
6. a separately authorized bounded device test for enabled capabilities.

No new SAEF helper or public API is justified by this decision. The existing
ControlLight runtime and SAEF helper composition remain sufficient.

## Legacy Core Consequence

The shared legacy ControlLight implementation remains required while retained
wrappers call it. It must not be removed, replaced wholesale or treated as
dead code. Retirement requires zero verified callers and a separate static and
dynamic audit.

## Gate Outcome

The v0.2 ControlLight rollout requirement applies to selected consumers, not
to every historical installation object. All seven selected consumers have
completed their migration gates. The other 22 have an explicit retain
decision and remain protected by source-regression checks.

No Symcon source, object, variable, event, profile, archive setting or device
state was changed by this scope decision.
