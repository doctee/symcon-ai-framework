# Artifact Closure Checklist

Complete in the existing private change/workstream record. Link evidence; do
not create another package solely to close this checklist. Use `not applicable`
with a reason rather than silently omitting a safety decision.

- [ ] State the work outcome, including failed, interrupted or uncertain runs.
- [ ] Identify producer/source revision, accountable owner and canonical record.
- [ ] Assign each produced logical unit a role and exact configured location;
      record justified path exceptions. Separate originals from transfer copies.
- [ ] For a new handover, reference the primary checkout's private Transfer
      designation and distinguish build, exchange and retained backup locations.
      Record the actual copy destination/hash only after the authorized copy and
      readback; a prepared path or old share screenshot is not transfer proof.
- [ ] Bind existing manifest/receipt/source hashes where available; do not
      modify immutable files or create a replacement identity.
- [ ] Mark evidence basis/date, incomplete inventories and unresolved references.
      Unknown size/identity is not zero/absent.
- [ ] Record runtime consumers, deployment/fileset pairing, recovery needs and
      ongoing observations; retain unresolved dependencies and safety holds.
- [ ] Identify required backups, their verification scope and retention minimum.
      A content copy may not preserve ACLs, ADS, timestamps or filesystem identity.
- [ ] State retained fixtures, compiler scratch, markers, exports and quarantine;
      name the owner and next review condition/date. Completion does not authorize
      their removal. Keep the last known usable recovery copy.
- [ ] Separate actions actually performed from planned or prohibited actions.
      State explicitly when no cleanup or live access occurred.
- [ ] For separately authorized cleanup, reference exact scope, backup and
      postflight receipt. Preserve historical gaps; never repeat a consumed run
      to manufacture missing evidence. Quarantine purge is a separate decision.
- [ ] Update current summary and next gate without rewriting old reports. Check
      the canonical workstream handover before transfer. Do not revoke another
      workstream's hold or infer authority from its historical approval.

See [the storage standard](../../standards/ARTIFACT_STORAGE_STANDARDS.md) and
[workstream coordination](../../project/WORKSTREAM_COORDINATION.md).
